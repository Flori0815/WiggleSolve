# Flap systems

Landing-flap kinematics are generated by parametric functions in
`core-js/src/mechanisms/`. Each generator returns an ordinary
[definition](definition-format.md), so the result can be simulated in the web
app, exported, edited or driven from tests.

## Dropped-hinge flap

`droppedHingeFlap(params?)` — demo: *Aerospace → Dropped-Hinge Flap*
(`demos/dropped_hinge_flap.json`, regenerated with
`npm run generate:demos -w @wigglesolve/core`).

Coordinates: **x** chordwise aft, **y** up, **z** spanwise outboard (hinge axis).

```
            wing spar
  ──────────────●─────────────────────────────  y
                │ support rib                   ↑
   GRA axis  ◉──┤                               └─→ x (aft)
             │  │
       crank │  │  drive strut
             ●━━━━━━━━━━━━━━━━━━━━━━━━━━━━━●  lug
                                            ╲
                                    hinge    ●━━━━━━━━━━━━━━━━━━━━━━━  flap
                                (dropped)
```

### Topology

| Element | Per support *i* | Role |
|---|---|---|
| `support_i` | ground body | rib carrying the hinge `hinge_i` and the actuator axis `gra_i_axis` |
| `gra_i` | actuator (rotary, z) | geared rotary actuator; moves `crank_i` and `strut_i` |
| `crank_i` | body | output crank of the actuator |
| `strut_i` | body | drive strut; joints `strut_i_rot` (in-plane) and `strut_i_tilt` (rod-end tilt out of plane) |
| `flap_i_panel`, `flap_i_bracket`, `flap_i_hingeline` | bodies moved together | flap panel *i*: planform, lug bracket, hinge-axis segment; joint `flap_i_rot` |

### Determinacy

Two actuators on one rigid flap would over-constrain it: any rigging or
tolerance difference between them would load the flap instead of moving it.
The model resolves this the way the hardware does:

- **Split flap.** The flap is split at `splitStation`; each panel has one
  support and is positioned in rotation by its own actuator only.
- **Coupled at the split.** The panels share the hinge axis at the split
  (`flap_1_axis_split` ↔ `flap_2_axis_split`) — free in rotation about the
  span axis, coupled along it.
- **One spanwise-fixed support.** Support 1 (default) fixes the flap spanwise.
  Support 2 is spanwise free: a prismatic joint `support_2_slide` along the
  hinge axis. The free panel takes its spanwise position from the split
  coupling, so wing strain between the supports is absorbed by the slide and
  by the strut rod ends (`strut_2_tilt`), not by the structure.

### Solving sequence

1. **Spanwise coupling** — slide the free panel until its split point meets
   the fixed panel's split point.
2. **Four-bar per support** — swing the strut onto the lug (in plane, then
   tilt), swing the panel onto the strut, until strut end and lug coincide
   (`tolerance`, default 0.1 mm).

### Parameters

| Parameter | Default | Meaning |
|---|---|---|
| `span` | `[0, 3]` | flap root and tip station |
| `splitStation` | `1.5` | panel split |
| `supports` | `0.75` fixed, `2.25` free | one support per panel, exactly one fixed |
| `hinge` | `(0.60, −0.30)` | dropped hinge in the support plane |
| `lug` | `(0.55, −0.15)` | strut attachment on the flap |
| `leadingEdge`, `trailingEdge` | `(0.45, −0.05)`, `(1.45, −0.12)` | flap chord line |
| `actuatorAxis` | `(0.15, −0.05)` | actuator output axis |
| `crankLength`, `crankAngle` | `0.15`, `0` (pointing down) | crank in the reference pose |
| `driveRange` | `0° … 60°` | actuator travel |
| `flapRange` | `−70° … 10°` | admissible flap rotation (negative = trailing edge down) |
| `spanwiseTravel` | `±0.05` | slide of the free support |
| `strutTilt` | `±10°` | rod-end tilt of the drive struts |

With the defaults, 60° of actuator travel deflects the flap by about 49°;
the transmission angle stays above 64° over the full travel (no toggle).

### Verification

`core-js/tests/flaps.test.ts` checks the simulated flap angle against the
closed-form four-bar solution, independent panel deflection with unequal
drives, the split coupling, wing strain at the free support and parameter
validation. `test-suite/py` runs the same demo through the Python port.
